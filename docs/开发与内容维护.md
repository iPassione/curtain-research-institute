# 开发与内容维护

## 当前网页

V3（2026-11 起）网站由 Vite + TypeScript 构建。入口是根目录的 `index.html`，源码在 `src/`：

| 位置 | 内容 |
| --- | --- |
| `src/router.ts` | 单页路由。地址格式与以前相同：`?page=<馆藏或展室>`、`?article=<文章ID>&from=<馆藏>`，旧文章 ID 由别名表兼容 |
| `src/routes/` | 首页、馆藏、文章、未找到页 |
| `src/features/` | 航海图、方位图与施法图解、人物关系、诸界观测与巫师日常、展室、术语批注、阅读位置、全站检索 |
| `src/gl/` | 三维场景：首页「穿过帷幕」、立体航海图、施法台、诸界下潜，以及全站共用的画布与分档 |
| `src/styles/` | 样式。V3 之前的样式表收编在 `site` 层，V3 新增的在 `v3` 层 |
| `content/` | 馆藏、展室、术语表等数据，以及生成脚本的产物（`content/generated/`） |
| `assets-src/` | 原始图片与 SVG 图版；`assets-src/data/` 下是供着色器读取的数据图（如航海图高度图） |
| `public/` | 原样发布的文件：自托管字体、第三方许可 |
| `dist/` | 构建产物，也是 Sites 发布的目录。提交进仓库，但不要手工修改 |

安装 Node.js 22 或更新版本，在仓库根目录安装一次依赖：

```sh
npm install
npx playwright install chromium   # 运行测试前需要一次
```

常用命令：

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 整理内容数据 → 生成多尺寸图片 → 类型检查 → 打包，结果写入 `dist/` |
| `npm run preview` | 在 `http://127.0.0.1:8765/` 预览 `dist/` |
| `npm run dev` | 开发服务器，带热更新（`http://127.0.0.1:5173/`） |
| `npm run content` | 依次运行三个正文与馆藏生成脚本，再整理内容数据 |
| `npm test` | Playwright 测试（需先 `npm run build`） |

## 文章修订

`humanizer/revised/<文章ID>.json` 为逐篇修订稿，可编辑 `title`、`subtitle`、`lead`、`chapters`。篇名修订自 2026-11-09 起由 `title` 字段覆盖展示标题；旧稿缺少此字段时沿用原题。保留文章 `id`、馆藏归属和来源笔记名。`humanizer/baseline-articles.json` 是原文基线，`humanizer/round2/current-before.json` 是第二轮开始时的全文快照，供审校对照。

改完后在仓库根目录运行：

```sh
node build-humanized.cjs
npm run build
```

三个生成脚本与各自的源稿：

| 脚本 | 源稿 | 生成 |
| --- | --- | --- |
| `node build-humanized.cjs` | `humanizer/revised/*.json` | `content/generated/humanized-articles.js`、`humanizer/revision-report.json` |
| `node build-collections.mjs` | `collection-longform.json`、`collection-expansions.json` | `content/generated/collection-longform.js` |
| `node build-editorial.mjs` | `editorial-*.json`、`content/legacy/*.js` | `content/generated/catalogue.js`、`editorial-audit.json`、`editorial-additions.json` |

不确定改了哪类源稿时，`npm run content` 会依次运行这三个脚本。`npm run build` 再把馆藏拆成目录清单与每篇一个 JSON（修订稿在这一步合并）。提交正文变更时，把改过的源稿、`content/generated/` 下的生成文件和 `dist/` 一同提交。直接修改 `content/generated/` 或 `dist/` 会在下次生成时被覆盖。

`prepare-humanizer.cjs`、`humanizer/owner-polish.cjs`、`humanizer/final-review.cjs`、`connect-fieldrooms.cjs`、`revise-worlds-focus.cjs`、`complete-editorial-history.py` 是已执行的一次性迁移或编辑工具，部分仍指向 V3 之前的 `dist/` 路径。运行前阅读脚本和相关编辑记录，不要依次盲跑所有工具。

`tests/baseline/content-baseline.json` 记录 V3 迁移前 53 篇文章的结构与全文指纹，`npm run verify:content` 用来确认迁移没有改动内容；之后有意修改正文，被改的文章会在这里报出差异，属于预期，日常改稿不必运行。

## 展室、栏目与术语

- 三间展室的数据：`content/fieldrooms/exhibit-data.js`、`travel-data.js`、`street-data.js`，直接编辑后 `npm run build`。专题说明见 [FIELDROOMS](专题/FIELDROOMS.md)。
- 诸界观测、巫师日常两个栏目与四篇正文：`content/collection-content.js`。栏目里交互面板的文字（六大世界、生活专题、货币换算）在 `src/features/collections.ts`；方位图、施法阶段与人物关系在 `src/features/atlas.ts`。
- 术语批注表：`content/glossary.json`，每条只写「词 → 文章 ID」，可用 `match` 补充别的写法。悬停卡片显示所指文章自己的类别与提要，不另写释义。改完运行 `npm run build`；在其他文章正文里一次都没出现的词条会被略去并打印提示。
- 全站检索的索引由构建自动生成，无需手工维护。

## 插画与图片

原始图片放在 `assets-src/`，`npm run build` 生成 AVIF 与 WebP 的多尺寸版本，原图不进入 `dist/`。`assets-src/data/` 下的数据图原样复制、不压缩。

航海图的浮雕高度图由 `node scripts/derive-height.mjs` 从 `assets-src/nautical-chart.png` 派生（首页穹顶内的大陆和地理馆立体航海图共用），换了航海图才需要重新运行。

器物主图使用静态插画。绘图工具及先前三维实现的记录见 [绘图说明](../tools/drawing/README.md)，普通预览无需安装这些工具。

## 三维场景

- 启用条件：支持 WebGL2、有显卡加速、未开启「减弱动态效果」、未开省流模式。软件渲染一律使用静态版本。原有按钮、文字与交互始终可用，三维只是叠加的画法。
- 调试参数：`?gl=full|lite|static` 强制档位（强制时不自动降档），`?debug=gl` 左下角显示档位与帧率。
- 历史长卷与人物星座图用 2D 画布，不受上面的条件限制，只在「减弱动态效果」时保留原样。
- 截图脚本（先 `npm run preview`）：`tests/visual/journey-shots.mjs`、`chart-shots.mjs`、`casting-shots.mjs`、`worlds-shots.mjs`、`stories-shots.mjs`，用法 `node tests/visual/<名>.mjs http://127.0.0.1:8765 <输出目录>`。截图目录不纳入版本。
- 视觉规则与每个场景的设定依据见 [视觉规范](设计/DESIGN.md)；施工方案见 [FRONTEND-V3](设计/FRONTEND-V3.md)，进度与接续见 [V3 接续说明](V3-接续说明.md)。

## 测试

```sh
npm run build
npm test
```

普通页面先跑：七个馆藏、三间展室及其地址参数、文章与旧别名、未找到页、单页切换与返回、检索、术语、阅读位置、货币换算、航海图与施法交互。三维场景（首页、航海图、施法台、诸界）在其后分组依次单独跑：测试环境没有显卡加速，WebGL 由 CPU 模拟，和其他测试同时跑会互相拖慢。

移动网站源码或素材时，同步检查样式、脚本、素材与动态加载路径。移动文章源数据或根目录生成脚本时，先检查其相对路径约定。
