## 三、做事的规矩

这些是这几天和用户形成的习惯，新会话请照做。

- **沟通**：用中文。每做完一个阶段，先给截图（桌面完整档、精简档、手机），列出调试中改掉的问题和没验证的部分，再问要不要并入。用户回「并入」才合并。
- **分支**：每个阶段从 `main` 开 `feat/v3-<名称>`，用户说「并入」后快进合并回 `main`。推送前问用户；不发布；不改 `.openai/hosting.json`。
- **工作位置**：不要直接在用户的检出 `Y:\Obsidian\帷幕\curtain-research-institute` 里改，另开工作树或分支，用户检出只用来快进合并。
- **提交**：中文提交信息，按逻辑拆分。作者沿用仓库已有的 `iPas <ipas@local.invalid>`（`git -c user.name=iPas -c user.email=ipas@local.invalid commit …`），末尾加 `Co-Authored-By` 行。`dist/` 是发布目录，构建产物要一起提交。
- **内容红线**：不改正文、摘要、展室文字和设定数据；不新增设定；可视化只表达馆藏里已写明的关系；不用公开馆藏之外的句子；发现问题列出来交给用户。
- **三维场景的通则**：
  - 支持 WebGL2、有显卡加速、未要求减弱动态、未开省流模式时才启用，否则页面与原版完全相同。软件渲染（SwiftShader 等）一律走静态版。
  - 全站只有一个画布，由 `src/gl/stage.ts` 管理；场景实现 `GLScene` 接口，离开页面时卸载。
  - 原有按钮、文字和交互保持可用，三维只读状态来画；画布对读屏隐藏，重复的视觉文字也对读屏隐藏，并提供跳过链接。
  - 新代码按需加载；新样式放在 `@layer v3`。

## 四、怎么验证

```sh
npm install          # 依赖装在各自的检出里，换机器或新工作树后要先装
npm run build        # 内容 → 图像 → 类型检查 → 打包，产物在 dist/
npm test             # 普通页面先跑；首页、航海图、施法台、诸界四组三维测试依次单独跑
npm run preview      # http://127.0.0.1:8765/
```

- 地址参数：`?gl=full|lite|static` 强制档位；`?debug=gl` 显示档位与帧率。
- 截图脚本（需先起预览服务；它们用本机显卡，比测试环境更接近真实效果）：
  `tests/visual/journey-shots.mjs`、`chart-shots.mjs`、`casting-shots.mjs`、`worlds-shots.mjs`，用法：`node tests/visual/<名>.mjs http://127.0.0.1:8765 <输出目录>`。
- 测试环境没有显卡加速，WebGL 由 CPU 模拟，所以三维测试都用 `?gl=` 强制档位，并分组依次运行。如果三维测试偶发卡在 `data-gl="loading"`，先看 `tests/casting.spec.ts` 里诊断信息的写法，读 `window.__curtainStage` 的状态。
- 跨浏览器：普通页面的测试在 Chromium、Firefox、WebKit 上都跑过（`CROSS=1`，见《开发与内容维护》）；四个三维场景在三者上都能渲染。Firefox 与 WebKit 会隐藏显卡名称，网站无法据此识别软件渲染，只能靠帧率自动降档。
- 还没有在真机上核对：iPhone/iPad 上的 Safari（施法台用浮点纹理，尤其要看）、安卓手机、集成显卡笔记本。Playwright 的 WebKit 不等于 iOS Safari。
